How I work

A few things I actually believe, not just say.

01

The UI hides options; the server enforces them. I learned this the direct way after a role check that only lived in the frontend on an early build of HostelMania. Every permission check I write now happens server-side, independent of whatever the interface already decided to show.

02

I'd rather write the boring test than debug the exciting bug. On a solo, deadline-driven project it's tempting to skip tests entirely. The times I skipped them cost me more hours re-verifying by hand than writing them would have.

03

A shortcut that's fast today is rarely fast in thirty days. Tangled logic is quick to write and slow to untangle later. I try to separate concerns early, even when it feels like unnecessary structure for a small project.

04

If I can't explain why I chose a tool, I probably chose it for the wrong reason. I want to be able to defend every technology decision on a project, not just list it as a tag.
