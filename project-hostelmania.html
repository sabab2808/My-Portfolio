The problem

Hostel canteens at the university were running food ordering manually — paper lists, verbal requests, and no clear record of who ordered what or paid for it. That meant long queues, mistakes in orders, and no easy way for canteen staff to plan food preparation ahead of time. Students needed a simple way to order and pay online; staff needed a dashboard to manage and fulfill those orders reliably.

02

The approach

I designed HostelMania around a clear separation of concerns: a student-facing ordering interface, a staff dashboard for managing orders, and a backend that handles authentication, order state, and payments consistently across both.

  • AuthRole-based login separating students and canteen staff, so each sees only what they need.
  • DataA relational MySQL schema for users, menu items, and orders, keeping order history queryable and accurate.
  • PaymentsIntegrated payment handling so orders are confirmed only once payment is settled.
  • InterfaceA responsive frontend so ordering works as well from a phone in a hostel room as from a desktop.

A closer look at the code

The pattern below is representative of how role checks work throughout the backend — re-verified server-side on every request, never trusted from the client. It's the direct fix for the auth bug described in my build notes. 

// order.controller.php — updating an order's status
// the UI only shows this action to staff, but the server
// re-checks the session role independently, every time.
function updateOrderStatus($orderId, $newStatus) {
    $session = getCurrentSession();

    if ($session->role !== 'staff') {
        return respond(403, 'Not authorized to update orders.');
    }

    $order = Order::find($orderId);

    if (!$order || $order->payment_status !== 'paid') {
        // an order can't move to "preparing" unless payment
        // already confirmed — no half-updated states.
        return respond(409, 'Order is not in a valid state.');
    }

    $order->transitionTo($newStatus);
    return respond(200, $order);
}
This is a representative reconstruction of the real pattern, written to be readable outside the full codebase — the actual file has more validation around it.
